第25章 硬件调试技巧：逻辑分析仪使用、示波器抓取时序、JTAG/SWD调试技巧

做Bootloader开发，说白了就是跟硬件打交道。你代码写得再漂亮，硬件不配合也是白搭。我见过太多开发者，软件逻辑天衣无缝，一烧进去就死机，然后对着屏幕发呆。这时候，硬件调试工具就是你的第三只眼。

今天咱们聊聊三样东西：逻辑分析仪、示波器、还有JTAG/SWD调试器。这三样东西，我几乎天天用。嗯，一个一个来。

逻辑分析仪：看信号的“逻辑”

逻辑分析仪，说白了就是看高低电平的。它不关心电压具体是多少，只关心是0还是1。你想想看，SPI、I2C、UART这些协议，本质上不就是一堆0和1在线上跳来跳去吗？

什么时候用逻辑分析仪？

  • 调试I2C通信时，看SCL和SDA的时序对不对
  • 分析SPI的片选信号、时钟和数据是否对齐
  • 抓取UART的起始位、数据位、停止位
  • 测量两个事件之间的时间间隔

我个人习惯：调试Bootloader时，我会在关键函数入口和出口各拉一个GPIO。然后用逻辑分析仪同时抓这个GPIO和通信总线。这样一眼就能看出，代码执行到哪一步时通信出了问题。

实际案例：有一次我调试一个从NAND Flash启动的Bootloader，死活读不到正确的数据。代码逻辑看了三遍都没问题。最后用逻辑分析仪一抓，发现片选信号在数据读取过程中被意外拉高了。原来是GPIO复用配置搞错了。你说气不气人？

示波器：看信号的“质量”

逻辑分析仪看“有没有”，示波器看“好不好”。

示波器能告诉你：

  • 电压幅值够不够（3.3V的信号是不是只有2.8V？）
  • 信号有没有毛刺（上升沿有没有抖动？）
  • 时序是否满足建立时间和保持时间
  • 电源纹波大不大

什么时候必须用示波器？

  • 调试外部晶振是否起振、频率是否准确
  • 检查复位信号的波形——复位时间够不够？
  • 看电源上电顺序（多路电源时尤其重要）
  • 分析高速信号（比如QSPI Flash的时钟频率超过50MHz时）

注意：示波器的带宽要够。你测100MHz的时钟，至少要用200MHz带宽的示波器。我曾经用100MHz示波器去测100MHz时钟，看到的波形全是正弦波，根本看不出方波的样子。嗯，这是个坑。

抓取时序的小技巧：

  1. 用示波器的“触发”功能。设置一个合适的触发电平，比如抓UART的起始位，就触发在下降沿。
  2. 配合“单次触发”模式。Bootloader启动时只发一次数据，用普通模式根本抓不到。
  3. 探头的地线要短。地线越长，引入的噪声越大，测出来的波形越难看。

JTAG/SWD调试技巧

JTAG和SWD，是嵌入式开发的“手术刀”。没有它，你只能靠printf和LED灯来猜问题。有了它，你可以单步执行、看寄存器、改内存。

JTAG vs SWD：怎么选？

特性 JTAG SWD
引脚数 5根（TMS, TCK, TDI, TDO, nTRST） 2根（SWDIO, SWCLK）
速度 快（并行传输） 稍慢（串行）
调试能力 支持边界扫描 仅调试
适用场景 FPGA、复杂SoC ARM Cortex-M系列

我个人建议：做Bootloader开发，SWD就够用了。除非你要做边界扫描测试，否则没必要占用那么多GPIO。

SWD调试的实战技巧

1. 连接不上？先检查硬件

  • SWDIO和SWCLK有没有上拉电阻？很多MCU要求外部上拉。
  • 目标板有没有供电？调试器不供电时，要单独给板子上电。
  • 复位引脚有没有被拉低？有些调试器需要复位信号。

避坑指南：我曾经遇到一个情况，SWD死活连不上。折腾了两小时，最后发现是调试器的线太长了。超过20cm的杜邦线，在高频下信号质量会严重下降。换了一对10cm的线，一次就连上了。

2. 调试Bootloader的特殊之处

Bootloader跟普通应用程序不一样。它一上电就开始跑，而且往往在Flash的起始地址。调试时要注意：

  • 设置断点时，别设在中断向量表上。那里存的是地址，不是代码。
  • Bootloader通常会重映射中断向量表。调试时要确认映射后的地址对不对。
  • 如果Bootloader要跳转到应用程序，可以在跳转前设一个断点，检查所有外设状态。

3. 用脚本自动化调试

很多调试器支持脚本。比如用J-Link的Commander，可以写命令脚本：

// 连接目标
connect
device STM32F407VG
si SWD
speed 4000

// 擦除并烧写
erase
loadfile bootloader.bin 0x08000000
verifybin bootloader.bin 0x08000000

// 设置断点
setbp 0x08000100

// 运行
go

这样做的好处是，每次修改代码后，一键就能完成烧写和调试。不用每次都手动点来点去。

三种工具的配合使用

说实话，这三种工具不是互相替代的，而是互补的。我一般这样用：

  • 第一步：用逻辑分析仪看协议层有没有问题。比如I2C的地址对不对，ACK有没有收到。
  • 第二步：如果协议没问题但数据不对，用示波器看信号质量。是不是上升沿太缓？是不是有毛刺？
  • 第三步：用JTAG/SWD单步执行，看代码逻辑和寄存器值。确认软件有没有按预期执行。

我的经验：有一次调试SPI Flash驱动，逻辑分析仪显示数据发送和接收的时序完全正确。但读回来的数据全是0xFF。用示波器一看，MISO引脚上的电压只有1.8V，而MCU的IO口是3.3V的。原来是电平不匹配。这个问题，光靠逻辑分析仪是看不出来的。

总结一下

硬件调试，说白了就是“眼见为实”。不要相信你的代码，要相信你看到的波形。逻辑分析仪看协议，示波器看信号质量，JTAG/SWD看代码执行。三样东西配合好了，再难的问题也能找到根因。

嗯，最后说一句：别怕用这些工具。刚开始可能会觉得麻烦，但用顺手了，你会发现它们比printf好用一百倍。真的。
